# 06 · M365 与 D365 集成概述

> D365 CRM 和 M365 共享同一个租户、同一套 Entra ID 身份体系——它们天然可以深度集成，而不是两个独立系统的"对接"。本章梳理集成的全景图、常见场景和架构模式。

## 1. 为什么要集成

| 业务诉求 | 没有集成时 | 集成后 |
|---|---|---|
| 销售在 CRM 里跟进客户，同时要用 Teams 沟通 | 两个系统来回切换，聊天记录和客户信息脱节 | Teams 里直接嵌入客户卡片，聊天上下文自动关联到 CRM 记录 |
| 客户发邮件到销售邮箱 | 邮件和客户活动分散在 Outlook 和 CRM 两处 | 邮件自动同步到 Dataverse 的 Timeline，Outlook 里也能看 CRM 数据 |
| 合同/报价文档管理 | CRM 里附件散落，版本混乱 | 文档统一存 SharePoint，CRM 里直接引用和预览 |
| 管理层要看销售报表 | 手动从 CRM 导数据再做 PPT | Power BI 直连 Dataverse + M365 数据，自动刷新 |

**核心价值**：数据流动起来，用户在一个地方就能完成跨系统的工作，不需要来回切换。

## 3. 常见集成场景分类

### 3.1 按数据流向

| 方向 | 典型场景 | 实现方式 |
|---|---|---|
| M365 → Dataverse | Outlook 邮件自动同步到客户时间线 | Dynamics 365 App for Outlook（官方内置） |
| M365 → Dataverse | Teams 聊天中创建 CRM 记录 | Teams 嵌入 Power Apps / Virtual Table |
| Dataverse → M365 | 新客户自动创建 SharePoint 文档库 | Power Automate 流 |
| Dataverse → M365 | 工单状态变更通知发到 Teams 频道 | Power Automate + Teams 连接器 |
| 双向 | CRM 里管理 SharePoint 文档 | Virtual Table + SharePoint 集成 |
| 双向 | 日历同步（CRM 约会 ↔ Outlook 日历） | Dynamics 365 App for Outlook + Server-Side Sync |

### 3.2 按集成深度

| 层级 | 说明 | 复杂度 | 举例 |
|---|---|---|---|
| L1 · 开箱即用 | 微软官方提供的集成开关 | 低 | Server-Side Sync、Dynamics 365 App for Outlook |
| L2 · 低代码流 | Power Automate 连接两个系统 | 中低 | 新建客户 → 自动创建 Teams 群组 |
| L3 · 嵌入体验 | 在一个系统里嵌入另一个系统的数据 | 中 | Teams 选项卡里显示 CRM 客户详情（IFRAME / Power Apps 嵌入） |
| L4 · API 级集成 | 通过 Graph API + Dataverse Web API 深度打通 | 中高 | 自定义 Azure Function 监听 Graph 变更通知，写入 Dataverse |
| L5 · 数据虚拟化 | Virtual Table 让 M365 数据在 Dataverse 里"像本地表一样"查询 | 高 | SharePoint 列表映射为 Virtual Table，CRM 表单直接展示 |

## 4. 集成技术栈对照（D365 开发者视角）

| 你熟悉的 D365 集成方式 | M365 对应/扩展 | 备注 |
|---|---|---|
| 插件（Plugin）拦截 CRUD | Power Automate 触发器 / Dataverse 变更通知（webhook） | M365 侧没有插件管道，事件驱动靠 webhook |
| 自定义工作流 / 工作流活动 | Power Automate 流 | 逻辑几乎一致，触发器更丰富 |
| IFRAME 嵌入外部页面 | Teams 选项卡 / SPFx Web 部件嵌入 | 技术栈从 HTML IFRAME 升级到 Teams manifest / SPFx |
| Azure Service Bus 集成 | Azure Functions + Graph webhook / Event Grid | 事件驱动架构升级 |
| 报表（SSRS） | Power BI + Dataverse 连接器 | 更现代，支持 M365 数据源 |
| Virtual Entity | **Virtual Table**（同名升级） | 数据源从外部 API 扩展到 SharePoint、Graph 等 |

## 5. 集成前提：统一身份

所有集成场景都基于一个前提——**D365 和 M365 在同一个 Entra ID 租户下**。

这意味着：
- 用户只需登录一次，就能访问 CRM 和 M365 服务（SSO）
- 应用注册（App Registration）在同一个地方管理
- 权限可以跨系统分配（比如同一个用户既是 CRM 销售角色，又有 SharePoint 站点读取权限）
- 服务间调用可以用同一个 OAuth 令牌体系

> 如果你的 D365 和 M365 不在同一个租户（比如收购场景），需要先做租户合并或使用跨租户认证，这是另一个大话题。

## 6. 本章小结

- D365 和 M365 的集成不是"对接两个系统"，而是"打通同一个平台的不同服务"
- 集成场景按数据流向和深度分类，从开箱即用到 API 级深度打通都有
- Power Automate 是低代码集成的首选工具，Graph API + Dataverse Web API 是代码级集成的基础
- 统一身份（Entra ID）是所有集成的前提
