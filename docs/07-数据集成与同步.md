# 07 · 数据集成与同步

> D365 CRM 和 M365 之间的数据流动是集成的核心。本章按数据域（邮件、文档、日历、Teams、用户）逐一讲解同步方案，每个方案都给出"开箱即用 → 低代码 → 代码级"三个层次的实现路径。

## 1. 邮件 ↔ 客户记录同步

这是最常见的集成需求：让 Outlook 里的邮件自动关联到 CRM 客户。

### 1.1 方案对比

| 方案 | 层次 | 数据流向 | 适用场景 |
|---|---|---|---|
| **Dynamics 365 App for Outlook** | 开箱即用 | 双向 | 标准 CRM 邮件同步，首选 |
| **Server-Side Sync** | 开箱即用 | 双向 | 邮件 + 约会 + 联系人 + 任务全量同步 |
| **Power Automate** | 低代码 | 单向/自定义 | 需要自定义逻辑（如按规则分类、触发后续流程） |
| **Graph API + Dataverse Web API** | 代码级 | 自定义 | 复杂业务逻辑、非标准数据映射 |

### 1.2 Dynamics 365 App for Outlook（推荐首选）

**它能做什么**：
- 用户在 Outlook 里发邮件时，可以手动"设置关于"（Set Regarding）把邮件关联到 CRM 记录
- 管理员可以配置自动同步规则：来自某域名的邮件自动关联到对应客户
- 在 Outlook 侧边栏直接查看客户的 CRM 信息

**配置步骤**（管理员）：
1. D365 管理中心 → 设置 → 电子邮件 → 启用 Server-Side Sync
2. 部署 Dynamics 365 App for Outlook（用户从 CRM 设置里一键安装）
3. 配置同步方向：CRM → Exchange、Exchange → CRM、或双向

**D365 开发者视角**：
- 和以前用 Email Router / 插件同步的体验完全不同——现在是微软托管的服务，不需要维护
- 同步逻辑在"同步设置"里配置，不需要写代码
- 如果内置规则不够用，再考虑 Power Automate 或代码方案

### 1.3 Power Automate 自定义邮件处理

当内置同步无法满足需求时，用 Power Automate 做自定义逻辑：

```
触发器：When a new email arrives (V2) — Outlook 连接器
   ↓
条件：发件人域名匹配 CRM 客户？
   ↓
是 → 查找 Dataverse 客户记录
   ↓
创建 activitypointer 记录（邮件活动）
   ↓
可选：发送 Teams 通知给销售
```

**关键连接器**：
- Outlook（Office 365 Outlook）：`When a new email arrives (V2)`、`Send an email (V2)`
- Dataverse：`Add a new row`、`List rows`、`Update a row`

### 1.4 Graph API 代码级方案

```csharp
// 读取用户邮件
var messages = await graphClient.Me.Messages
    .GetAsync(config =>
    {
        config.QueryParameters.Top = 50;
        config.QueryParameters.Select = new[] { "subject", "from", "receivedDateTime", "bodyPreview" };
        config.QueryParameters.Orderby = new[] { "receivedDateTime desc" };
    });

// 写入 Dataverse（通过 Dataverse Web API，和 D365 里一样）
var emailRecord = new Entity("email");
emailRecord["subject"] = message.Subject;
emailRecord["description"] = message.BodyPreview;
await dataverseClient.CreateAsync(emailRecord);
```

**什么时候用代码方案**：
- 需要复杂的邮件解析（如提取附件中的结构化数据）
- 需要跨多个邮箱聚合
- 内置连接器和 Power Automate 性能不够

## 2. 文档 ↔ CRM 记录同步

### 2.1 SharePoint 集成（推荐）

D365 CRM 原生支持将 SharePoint 作为文档管理系统：

| 功能 | 说明 |
|---|---|
| 基于记录的文件夹 | 每个 CRM 记录（客户、联系人、工单）自动对应一个 SharePoint 文件夹 |
| 文档时间线 | CRM 记录里直接显示关联的 SharePoint 文档 |
| 在线预览/编辑 | 在 CRM 表单里直接预览 Office 文档，点编辑跳转到 Office Online |
| 权限继承 | SharePoint 权限可以自动跟随 CRM 记录的所有者 |

**配置路径**：
1. D365 设置 → 文档管理 → 启用基于 SharePoint 的文档管理
2. 选择要集成的 SharePoint 站点
3. 选择哪些表（entity）需要文档管理
4. 完成

### 2.2 Virtual Table 方案（高级）

把 SharePoint 文档库映射为 Dataverse Virtual Table，这样在 CRM 里可以像查本地表一样查 SharePoint 数据：

```
SharePoint 文档库
    ↓ (Virtual Table 数据提供程序)
Dataverse Virtual Table
    ↓
CRM 视图 / 表单 / 报表直接使用
```

**适用场景**：
- 需要在 CRM 里做复杂的文档搜索和筛选
- 文档元数据需要和 CRM 数据做关联查询
- 需要在 Power BI 报表里同时展示 CRM 数据和文档信息

### 2.3 OneDrive 集成

如果文档不需要集中管理，也可以用 OneDrive：
- 每个用户自己的 OneDrive 里存个人工作文档
- 通过 Power Automate 把 CRM 触发生成的文档存到指定用户的 OneDrive
- 适合轻量级、个人化的文档场景

## 3. 日历 / 约会同步

### 3.1 Server-Side Sync 方案

和邮件同步一样，日历也是通过 Server-Side Sync 实现：

| 同步对象 | Dataverse 实体 | Exchange 对象 |
|---|---|---|
| 约会 | appointment | Appointment |
| 任务 | task | Task |
| 电话/传真 | phonecall / fax | 不直接同步，需要自定义 |

**同步方向**：
- CRM → Exchange：CRM 里的约会出现 Outlook 日历上
- Exchange → CRM：Outlook 里创建的约会同步到 CRM
- 双向：两边都能创建，自动合并冲突

### 3.2 Graph API 日历操作

```csharp
// 读取用户日历事件
var events = await graphClient.Me.Calendar.Events
    .GetAsync(config =>
    {
        config.QueryParameters.Top = 20;
        config.QueryParameters.Select = new[] { "subject", "start", "end", "location" };
    });

// 创建新事件
var newEvent = new Event
{
    Subject = "客户拜访",
    Start = new DateTimeTimeZone { DateTime = "2026-11-05T10:00:00", TimeZone = "China Standard Time" },
    End = new DateTimeTimeZone { DateTime = "2026-11-05T11:00:00", TimeZone = "China Standard Time" },
    Location = new Location { DisplayName = "客户公司" }
};
await graphClient.Me.Calendar.Events.PostAsync(newEvent);
```

## 4. Teams 与 CRM 数据联动

### 4.1 Teams 频道通知

最常见的场景：CRM 里发生重要事件时，通知发到 Teams 频道。

**Power Automate 实现**：
```
触发器：Dataverse — When a row is added/modified/ deleted
   ↓
条件：表 = incident（工单）且 statuscode = 已解决
   ↓
动作：Teams — Post message in a chat or channel
   ↓
消息内容：工单标题 + 客户名 + 解决时间
```

### 4.2 Teams 选项卡嵌入 CRM 数据

在 Teams 里直接查看 CRM 数据，不需要切换到 D365 应用：

| 嵌入方式 | 适用场景 | 技术 |
|---|---|---|
| 网站选项卡（Website tab） | 快速嵌入 CRM 表单/视图 | 直接填 CRM 表单 URL（需要 SSO） |
| Power Apps 选项卡 | 需要自定义交互逻辑 | 在 Teams 里嵌入一个 Canvas App，数据源是 Dataverse |
| 自定义 Teams 应用 | 深度集成体验 | Teams App + Tab SDK + Dataverse Web API |

### 4.3 Virtual Table 让 Teams 数据进 CRM

把 Teams 的频道消息、团队成员等映射为 Dataverse Virtual Table，在 CRM 里直接查询和关联：

```
Teams 频道消息
    ↓ (Virtual Table 数据提供程序)
Dataverse Virtual Table "teams_message"
    ↓
CRM 里可以：
- 在客户表单上显示该客户相关的 Teams 讨论
- 在报表里统计 Teams 活跃度
- 用 Power Automate 监听 Virtual Table 变化触发流程
```

## 5. 用户 / 组织架构同步

### 5.1 Entra ID 是统一数据源

D365 和 M365 的用户都来自同一个 Entra ID（Azure AD），不需要手动同步：

| 操作 | 影响 |
|---|---|
| 在 Entra ID 里新建用户 | 自动出现在 D365 的用户列表（需要分配 D365 许可证） |
| 在 D365 里禁用用户 | 只是禁用 D365 访问，Entra ID 用户还在 |
| 在 Entra ID 里删除用户 | D365 里该用户的所有记录变为"系统用户已删除"状态 |

### 5.2 安全组 / 团队同步

- Entra ID 的 **Microsoft 365 Group** 自动对应一个 Teams 团队 + SharePoint 站点 + Outlook 共享邮箱
- Dataverse 的 **团队（Team）** 可以关联到 Entra ID 的安全组
- 通过 Power Automate 可以实现：新建 M365 Group → 自动创建 Dataverse 团队并关联

## 6. 数据同步最佳实践

| 实践 | 说明 |
|---|---|
| 优先用开箱即用方案 | Server-Side Sync、SharePoint 集成——能不开代码就不开 |
| 低代码优先 | Power Automate 能做的不用写代码——维护成本低 |
| 代码方案要考虑幂等 | 同步逻辑要能重跑不产生重复数据——用唯一键判断 |
| 监控同步失败 | Power Automate 有运行历史；Server-Side Sync 有同步错误日志 |
| 注意 API 限流 | Graph API 和 Dataverse Web API 都有调用频率限制，批量操作要用 `$batch` / `ExecuteMultiple` |
| 增量同步优于全量 | 用 delta 查询（Graph）或变更跟踪（Dataverse）只同步变化的数据 |

## 7. 本章小结

- 邮件/日历同步首选 Server-Side Sync + Dynamics 365 App for Outlook
- 文档管理首选 SharePoint 集成，高级场景用 Virtual Table
- Teams 联动可以用 Power Automate 通知、选项卡嵌入、或 Virtual Table 反向同步
- 用户数据天然统一（Entra ID），不需要额外同步
- 三层实现路径：开箱即用 → 低代码 → 代码级，按需选择
