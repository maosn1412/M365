## 2. 关键结论（先看这个）

1. **SPFx 1.22 引入 Heft 构建链，1.23 起新项目只支持 Heft**。旧教程的 `gulp serve` / `gulp trust-dev-cert` 全部失效，对应新命令是 `npm run start`（heft start）和 `npx heft trust-dev-cert`。
2. **SPFx 1.23 没有纯本地工作台了**。`npm run start` 起的 webpack-dev-server 只提供 bundle/manifest（`https://localhost:4321/temp/build/manifests.js`），可视化调试必须打开租户托管工作台 `https://{租户}.sharepoint.com/_layouts/workbench.aspx?debugManifestsFile=...`。**⚠️ 托管工作台将于 2026-12-01 退役**，官方推荐改用 **SPFx Debug Toolbar**（由 SharePoint 在租户站点页面的调试 URL 中注入的工具栏）。**没有租户只能验证到"编译+本地服务"这一步。**
3. **SPFx 1.23.2 严格要求 Node >=22.14 且 <23**（见生成的 package.json `engines`）。本机原有 Node 26 不能直接用，必须用 nvm 切换。
4. Teams/Copilot 的 VS Code 扩展 ID 已从 `teamsdevapp.ms-teams-toolkit` 改为 **`TeamsDevApp.ms-teams-vscode-extension`**（改名 Microsoft 365 Agents Toolkit 后）。
5. 所有需要登录租户的步骤（Graph 真实调用、Teams 调试、SPFx 托管工作台）都**待注册 M365 开发者沙盒后进行**，指引见 [00-学习路线图.md](00-学习路线图.md) 第 4 节。

## 3. 搭建步骤实录

### Step 1 · nvm-windows + Node 22

```bash
winget install -e --id CoreyButler.NVMforWindows   # 装 nvm-windows 1.2.2（需点 UAC 授权）
```

装完自动识别已有 Node 20.18.1 / 26.7.0。环境变量：`NVM_HOME=C:\Users\mason\AppData\Local\nvm`，`NVM_SYMLINK=C:\nvm4w\nodejs`。

```bash
nvm install 22        # 装到 22.23.4
nvm use 22.23.4       # 切换（需管理员权限建符号链接，本机已通过）
node -v               # v22.23.4 ✓
```

⚠️ Git Bash 会话里 `nvm` 不在默认 PATH，需显式：
```bash
export NVM_HOME='C:\Users\mason\AppData\Local\nvm'
export NVM_SYMLINK='C:\nvm4w\nodejs'
"$NVM_HOME/nvm.exe" list
# 用 node 前：export PATH="/c/nvm4w/nodejs:$PATH"
```
（新开终端窗口会自动带新 PATH；旧会话需手动 export。）

### Step 2 · SPFx 工具链

```bash
npm i -g yo gulp-cli @microsoft/generator-sharepoint   # 全局安装（约 6 分钟）
```

生成示例项目（仓库内 `spfx-hello/spfx-hello`，Minimal/无框架模板）：

```bash
mkdir spfx-hello && cd spfx-hello
# 模板选择无对应命令行参数，需交互选择：方向键选 Minimal（无框架）
# 注：本仓库实际选的是 Minimal；若要练 React/Fluent UI，此处应选 React
yo @microsoft/sharepoint \
  --solution-name "spfx-hello" \
  --component-type "webpart" --component-name "HelloWorld" \
  --component-description "HelloWorld web part" --skip-install

cd spfx-hello   # 注意生成器会再嵌套一层同名目录
npm install
```

### Step 3 · 证书 + 本地服务验证

```bash
npx heft trust-dev-cert     # "Certificate successfully trusted." ✓
npm run start               # heft start --clean，起 webpack-dev-server :4321
```

验证结果：

```bash
curl -k https://localhost:4321/temp/build/manifests.js   # 200 ✓ bundle 正常产出
powershell -c "(Invoke-WebRequest 'https://localhost:4321/temp/build/manifests.js' -UseBasicParsing).StatusCode"   # 200 ✓ 证书已受信
```

> 注：Git Bash 的 curl 用自己的 CA 包、不走 Windows 证书库，所以 `curl` 不加 `-k` 会报证书错误——这是 curl 的问题，不代表证书没信任。浏览器/PowerShell 走 Windows 证书库，正常。

### Step 4 · Teams/Copilot 与 Graph 工具

```bash
# VS Code 扩展（ID 见上文"关键结论 4"）
# ⚠️ Marketplace CDN 直连极慢（约 44KB/s），在线安装会卡死。
# 解决办法：从 VS Code 扩展市场页面获取 VSIX 直链，curl 断点续传下载后离线安装：
# 直链格式（版本号/时间戳需从市场页面实际获取，不可照抄）：
curl -L -C - -o /tmp/atk.vsix \
  "https://TeamsDevApp.gallerycdn.vsassets.io/extensions/teamsdevapp/ms-teams-vscode-extension/<从市场页获取的版本号>/<从市场页获取的时间戳>/Microsoft.VisualStudio.Services.VSIXPackage"
"D:\Microsoft VS Code\bin\code" --install-extension /tmp/atk.vsix   # ✓ 已装 6.19.x

# SPFx Toolkit（PnP 出的 SPFx 辅助扩展，体积小可直接在线装）
"D:\Microsoft VS Code\bin\code" --install-extension m365pnp.viva-connections-toolkit   # ✓ v4.22.0

# CLI 形态（atk），CI/CD 或无 GUI 场景可用
npm i -g @microsoft/m365agentstoolkit-cli    # atk --version → 1.1.18 ✓

# CLI for Microsoft 365
npm i -g @pnp/cli-microsoft365               # m365 --version → 11.11.0 ✓
```

Graph Explorer（网页版，免安装）：[developer.microsoft.com/zh-cn/graph/graph-explorer](https://developer.microsoft.com/zh-cn/graph/graph-explorer)

## 4. 踩坑记录

| 坑 | 现象 | 解决 |
|---|---|---|
| Node 26 过新 | SPFx 要求 Node 22.x | nvm-windows 安装多版本切换 |
| nvm 在 Git Bash 找不到 settings.txt | `ERROR open \settings.txt` | 需先 `export NVM_HOME/NVM_SYMLINK` |
| 生成器嵌套目录 | 在自建 `spfx-hello` 里又生成一层 `spfx-hello` | `cd spfx-hello/spfx-hello` 再 npm install |
| yo 非交互参数不全 | `--which-framework react` 仍弹模板选择（Minimal/No framework/React） | 去掉该参数，交互选择模板；本仓库实际选了 Minimal |
| gulp 消失 | 生成的 package.json 没有 gulp | SPFx 1.23 已切 Heft，用 `npm run start` |
| 本地工作台 404 | `/temp/workbench.html` 404 | 1.23 起工作台托管在租户，本地只有 manifests |
| 扩展 ID 失效 | `teamsdevapp.ms-teams-toolkit` not found | 新 ID：`TeamsDevApp.ms-teams-vscode-extension` |
| Marketplace CDN 慢 | 在线安装扩展卡死（约 44KB/s） | curl 断点续传下载 VSIX（约 34MB）后 `code --install-extension` 离线安装 |

## 5a. Teams Tab 应用本地测试记录（2026-11-04）

新增传统 Teams 应用示例 `teams-tab-app/`，本地验证结果：

| 步骤 | 命令 | 结果 |
|------|------|------|
| 生成项目 | `atk new -c tab -n teams-tab-app -l typescript -i false -f .` | ✓ 项目生成于 `teams-tab-app/`（React 19 + TS + Vite 6 + Express） |
| 安装依赖 | `npm install` | ✓ 278 packages，含 `@microsoft/teams-js`、`@microsoft/teams.apps`、`react`、`vite` 等 |
| 构建 | `npm run build` | ✓ tsup 编译服务端（`dist/index.js` 1.38KB）+ Vite 编译前端（`dist/client/assets/index-xxx.js` 268KB） |
| 清单校验 | `atk validate --env dev` | ✓ All passed（需先设置 `TAB_ENDPOINT`/`TAB_DOMAIN` 临时值，provision 时会自动填入） |
| manifest 填充 | 更新 developer/description 占位符 | ✓ 与 my-first-agent 保持一致（developer.name="Mason"） |

**技术栈说明**：
- 服务端：`@microsoft/teams.apps`（ExpressAdapter）+ HTTPS（本地调试需要 SSL 证书）
- 前端：React 19 + `@microsoft/teams-js` v2（Teams AI Library v2）
- 双构建链：tsup（服务端，`tsconfig.node.json`）+ Vite（前端，`tsconfig.app.json`）
- 部署目标：Azure App Service（Bicep 模板在 `infra/`）

**与 my-first-agent 的关键差异**：

| 维度 | my-first-agent | teams-tab-app |
|------|---------------|---------------|
| 类型 | 声明式代理（无代码） | Teams Tab 应用（全代码） |
| 服务端 | 无 | Express + HTTPS |
| 构建 | atk 直接打包 | tsup + Vite 双构建 |
| 部署 | Copilot 租户目录 | Azure App Service + Teams 目录 |
| infra/ | 无 | 有（Azure Bicep） |

**待租户后验证**：F5 本地调试（自动 provision + 打开 Teams 网页版）、Azure 远程部署、Teams 中侧载测试 Personal Tab。
