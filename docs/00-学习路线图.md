# M365 开发学习路线图（面向 D365 CRM 开发者）

> 适用读者：有 Dynamics 365 CRM 开发经验（C#/JS、Dataverse、Web API、插件、Power Platform），转向 Microsoft 365 开发。
> 最后更新：2026-11-09

---

## 1. D365 与 M365 是什么关系

| | Dynamics 365 CRM | Microsoft 365 |
|---|---|---|
| 定位 | 业务应用（销售/客服/市场等 CRM 场景） | 生产力协作平台（Teams、SharePoint、Exchange、Office、Copilot） |
| 数据层 | Dataverse | Microsoft Graph（横跨邮件、日历、文件、用户、Teams、SharePoint…） |
| 扩展方式 | 插件（C#）、JS 表单脚本、PCF 控件、Power Automate | Graph API、SPFx、Teams 应用、Office 加载项、Copilot 扩展 |
| 身份认证 | Entra ID（Azure AD） | **同一个 Entra ID**——概念完全复用 |
| 低代码层 | Power Apps / Power Automate | **同一套 Power Platform**——你的经验直接可用 |

**关键认知**：D365 和 M365 共享同一个租户、同一套 Entra ID 身份体系、同一个 Power Platform。你不是从零开始，而是把已有的"Dataverse 思维"扩展到"Graph 思维"。

## 2. 知识映射表（D365 → M365）

| 你已掌握的 D365 概念 | M365 对应物 | 说明 |
|---|---|---|
| Dataverse Web API (`/api/data/v9.2`) | Microsoft Graph (`https://graph.microsoft.com/v1.0`) | 都是 OData REST，支持 `$select/$filter/$expand/$top` |
| Dataverse 表（entity） | Graph 资源（user/group/message/driveItem/listItem…） | Graph 资源跨工作负载，不限于 CRM |
| 插件 / 自定义 API（服务端 C#） | Azure Functions + Graph 订阅（webhook）/ 变更通知 | M365 没有"插件管道"，事件用 webhook 或轮询 delta |
| 表单脚本（客户端 JS） | SPFx Web 部件 / Teams 选项卡（TypeScript + React） | 前端技术栈升级为现代 TS/React 工具链 |
| PCF 控件 | SPFx Web 部件 / Fluent UI 组件 | PCF 的 React 经验直接迁移 |
| SDK 风格 `.NET` 开发 | Graph SDK for .NET (`Microsoft.Graph` NuGet) | 强类型 SDK，和 D365 SDK 体验类似 |
| 应用注册（App Registration） | **完全相同** | 同一个 Entra 应用注册门户 |
| 解决方案（Solution）打包 | Teams 应用包（manifest zip）/ SPFx `.sppkg` | 分发机制不同，思路类似 |
| Power Automate | Power Automate（同一产品） | 连接器里多了 Teams/SharePoint/Outlook 触发器 |

## 3. 三大方向学习路径

### 方向一：Microsoft Graph（建议最先学，地基）

- **阶段 1 概念**（约 2 小时）
  - [ ] 读 [01-Microsoft-Graph.md](01-Microsoft-Graph.md) 的 1–3 节
  - [ ] 在 Graph Explorer 里用示例账号跑 10 个查询
- **阶段 2 动手**（约 1 天）
  - [ ] 注册 Entra 应用，用 client credentials 调 `/users`
  - [ ] 用委托权限做一个"读取我的邮件+日历"的 .NET 控制台程序
  - [ ] 完成 MS Learn 路径：[Microsoft Graph 基础知识](https://learn.microsoft.com/zh-cn/training/paths/m365-msgraph-fundamentals/)
- **阶段 3 进阶**
  - [ ] 变更通知（webhook）+ delta 查询——对照理解 D365 插件/审计的替代方案
  - [ ] 批处理（`$batch`）、限流（429 重试）、分页（`@odata.nextLink`）
  - [ ] MS Learn：[了解用于 JavaScript 开发 Microsoft Graph 方案](https://learn.microsoft.com/zh-cn/training/browse/?products=m365&resource_type=learning%20path&roles=developer)

### 方向二：SPFx / SharePoint 开发

- **阶段 1 概念**（约 2 小时）
  - [ ] 读 [03-SPFx-SharePoint开发.md](03-SPFx-SharePoint开发.md)
  - [ ] 理解 SharePoint 站点/列表/文档库 与 Dataverse 表的差异
- **阶段 2 动手**（约 1–2 天，本地环境已搭好，见 [04-开发环境搭建手册.md](04-开发环境搭建手册.md)）
  - [ ] 跑通 `spfx-hello` 示例（本仓库已有）
  - [ ] 改 Web 部件属性面板，加自定义属性
  - [ ] 在部件里用 PnPjs 读当前站点列表（需租户）
  - [ ] MS Learn：[SharePoint 框架入门](https://learn.microsoft.com/zh-cn/training/modules/sharepoint-spfx-get-started/)
- **阶段 3 进阶**
  - [ ] SPFx 扩展（Application Customizer / Command Set）
  - [ ] 在 SPFx 里调 Microsoft Graph（MSGraphClient）
  - [ ] PnP 样例库临摹 2–3 个真实部件

### 方向三：Teams 应用 / Copilot 扩展

- **阶段 1 概念**（约 2 小时）
  - [ ] 读 [02-Teams应用与Copilot扩展.md](02-Teams应用与Copilot扩展.md)
  - [ ] 理解 Teams 应用清单（manifest）与 D365 解决方案打包的异同
- **阶段 2 动手**（需租户）
  - [ ] 用 Agents Toolkit 创建"声明式代理"并在 Copilot 里跑通
  - [ ] 创建 Teams 选项卡应用（个人选项卡）
  - [ ] MS Learn：[将应用发布到 Microsoft 365、Outlook 和 Teams 应用商店](https://learn.microsoft.com/zh-cn/training/browse/?products=m365&resource_type=learning%20path&roles=developer)
- **阶段 3 进阶**
  - [ ] 声明式代理 + API 插件（把现有 REST API 接入 Copilot）
  - [ ] 自定义引擎代理（M365 Agents SDK）
  - [ ] MS Learn：[使用 VS Code 通过 API 插件扩展 Copilot 的声明性代理](https://learn.microsoft.com/zh-cn/training/browse/?products=m365&resource_type=learning%20path&roles=developer)

### 方向四：D365 ↔ M365 集成（结合你的 D365 背景）

- **阶段 1 概念**（约 2 小时）
  - [ ] 读 [06-M365与D365集成概述.md](06-M365与D365集成概述.md) 了解集成全景
  - [ ] 读 [08-统一身份与认证.md](08-统一身份与认证.md) 理解 Entra ID 统一身份
- **阶段 2 动手**（需租户）
  - [ ] 配置 Server-Side Sync（邮件/日历同步）

- **阶段 3 进阶**
  - [ ] 在 Teams 里嵌入 Power Apps 选项卡展示 CRM 数据
  - [ ] 用 Graph API + Dataverse Web API 写一个自定义同步服务
  - [ ] 用 Power BI 做跨系统报表

### 方向五：Power Platform 进阶（你的经验直接可用）

- **阶段 1 概念**（约 1 小时）
  - [ ] 读 [09-Power-Platform集成方案.md](09-Power-Platform集成方案.md)
  - [ ] 理解 Power Platform 在集成中的定位
- **阶段 2 动手**（需租户）

  - [ ] 用 Canvas App 同时连接 Dataverse 和 SharePoint 数据源
  - [ ] 用 Power BI 连接 Dataverse 做一个销售仪表板
- **阶段 3 进阶**

  - [ ] 在 Teams 里部署自定义 Copilot

### 方向六：Outlook 加载项（Office Add-ins）开发（2026-11 新增）

> 背景：需要一个"Outlook 邮件 → 右侧任务窗格 → 第三方 SaaS/ERP 客户信息"的集成功能。现有五个方向只覆盖了 D365 App for Outlook（开箱即用），没有自定义 Outlook 加载项、Office.js、任务窗格和 NAA 认证的内容。
> 详见 [10-Outlook加载项开发.md](10-Outlook加载项开发.md) 与 [11-Outlook客户信息侧边栏方案评估.md](11-Outlook客户信息侧边栏方案评估.md)。

- **阶段 1 概念**（约 2 小时）
  - [ ] 读 [10-Outlook加载项开发.md](10-Outlook加载项开发.md) 的 1–4 节
  - [ ] 理解 XML 清单、加载项命令、任务窗格、权限级别（ReadItem / ReadWriteItem / ReadWriteMailbox）
  - [ ] 明确客户端能力矩阵（本方向以 Outlook Web + 新版 Outlook 为准）
- **阶段 2 动手**（约 1–2 天）
  - [ ] 用 Microsoft 365 Agents Toolkit 或 `yo office` 创建 Outlook 任务窗格加载项（`outlook-addin-demo`，规划中）
  - [ ] 侧加载到 Outlook Web / 新版 Outlook，验证按钮 → 任务窗格
  - [ ] 阅读模式读取 from / subject / body；撰写模式读取 recipients / body
  - [ ] 订阅 `ItemChanged` / `RecipientsChanged` / `AttachmentsChanged` 事件
  - [ ] 用 `office-addin-manifest validate` 校验清单
- **阶段 3 认证与集成**（约 2–3 天）
  - [ ] Entra 应用注册：SPA `brk-multihub://` 重定向 + Expose an API
  - [ ] NAA + MSAL.js 获取用户令牌，BFF 校验 JWT
  - [ ] BFF 调模拟 ERP API：客户匹配 → 新建（幂等/防重）→ 回显
  - [ ] iframe 可行性实验：CSP `frame-ancestors` 与第三方 Cookie 限制
  - [ ] 自由文本抽取：规则优先，LLM 辅助时必须人工确认
- **阶段 4 部署**（约 1 天）
  - [ ] M365 管理中心 Integrated Apps 集中部署 + 管理员同意
  - [ ] 日志、监控与失败降级

## 4. 账号准备（一次性，需自己操作）

1. 打开 [Microsoft 365 开发人员计划](https://learn.microsoft.com/zh-cn/office/developer-program/microsoft-365-developer-program)，点"立即加入"
2. 用个人 Microsoft 账户登录 → 完成资格验证
3. 设置 **E5 沙盒订阅**（含 25 个用户许可证 + Teams/SharePoint/Exchange）
4. 拿到沙盒租户后，就可以解锁上面所有"需租户"的步骤
